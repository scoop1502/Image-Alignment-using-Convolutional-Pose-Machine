1. The central design decision

The task is: given a 224×224 image of an insect, output the pixel locations of five anatomical landmarks. The obvious formulation is direct regression — a network ending in a fully-connected layer emitting ten numbers, trained with an L1 or L2 loss on coordinates. Your repository contains exactly that approach in dataset.py and train.py, and it was abandoned in favour of the heatmap formulation in insect_dataset.py and train_heatmap.py. Three mathematical reasons justify that choice.

Reason 1 — Direct regression destroys spatial structure

A convolutional feature map is equivariant to translation: shifting the input shifts the features. Formally, if Tδ is translation by δ and f is a convolutional stack, then

f(Tδ x) = Tδ/s f(x)

for stride s. A flatten-then-dense head discards this: the network must relearn, for every output unit, the relationship between feature position and coordinate value. A heatmap head preserves equivariance exactly — moving the landmark moves its predicted blob, with no parameters spent on the correspondence.

Reason 2 — Regression cannot express uncertainty or multimodality

Suppose the network is genuinely unsure between two plausible locations p1 and p2. Under a squared-error coordinate loss the optimal single output is the conditional mean:

p* = arg minp 𝔼[‖p − y‖²] = 𝔼[y] = ½(p1 + p2)

— the midpoint, which may be anatomically meaningless. A heatmap can place mass on both hypotheses and let the decoder or a downstream consumer resolve them. It also yields a confidence signal for free (the peak height), which is what the score column of the inference CSV reports.

Reason 3 — Dense supervision

Coordinate regression provides 10 scalars of training signal per image. The heatmap formulation provides 6 × 28 × 28 = 4,704 supervised values per image. Every spatial position receives a gradient at every step, which is why heatmap methods converge from far less data — a decisive advantage with 599 training images.

The consequence Everything that follows is a consequence of this one decision. The dataset must encode coordinates into heatmaps (Section 2), the network is an image-to-image map rather than an image-to-vector map (Section 3), the loss is pixel-wise MSE rather than coordinate error (Section 5), and inference must decode heatmaps back into coordinates (Section 6). The pipeline is a bijection sandwich: decode ∘ network ∘ encode−1.

2. Encoding: coordinates → heatmaps

Implemented in insect_dataset.py, lines 136–158.

2.1 Geometric normalisation

Let the annotated landmark be at (X, Y) in original image pixels and the annotated box be (x1, y1, x2, y2). Three operations map it into the network's frame (lines 104–116):

(1) translate:   (xc, yc) = (X − x1,   Y − y1)
(2) scale:   s = min( 224 / wcrop,   224 / hcrop )
(3) normalise:   (u, v) = (s·xc / 224,   s·yc / 224) ∈ [0,1]²

The min in (2) preserves aspect ratio; the shorter side is then zero-padded on the bottom and right (lines 119–120) to fill the 224×224 canvas. Padding at the bottom-right rather than symmetrically is what keeps the origin at (0,0) and makes the inverse transform in Section 6.2 a pure affine map with no padding offset.

2.2 Discretisation to the heatmap grid

The network predicts on a coarser lattice. With stride = 224 // 28 = 8, the grid is 28×28 and the landmark's cell is (line 140–141):

cx = ⌊ u · 28 ⌋,     cy = ⌊ v · 28 ⌋

The floor is a lossy step and it is the first hard limit on achievable accuracy. It is quantified in Section 7.

2.3 The Gaussian target

Rather than a one-hot indicator — which would give a gradient at exactly one of 784 positions and train very poorly — the target is a Gaussian bump centred on that cell (line 166):

(4) Hi(r, c) = exp( − [ (c − cx)² + (r − cy)² ] / 2σ² ),    σ = 5

Two post-processing steps follow (lines 143–144): values are clipped above at 1, and values below 0.0099 are set to exactly 0. The threshold defines an effective support radius, obtained by inverting (4):

rmax = σ √( −2 ln 0.0099 ) = 5 · √9.234 = 15.19 cells

This is the critical observation about σ. It is measured in heatmap cells, not pixels, so the blob's radius is 15.19 cells on a map that is only 28 cells wide — it covers more than half the map. In the 224-pixel canvas that is a radius of 122 px. Canonical CPM implementations use σ ≈ 1–2 cells.

The flatness near the peak is the operative problem: a one-cell error changes the target by 2%, so the loss landscape around the correct answer is nearly flat and provides little pressure to localise precisely. This is the mathematical origin of the diffuse predictions seen at inference.

2.4 Channel selection and the background channel

Of the eight annotated landmarks only five are kept (line 147), namely indices [3,4,5,6,7] zero-based, which are landmark IDs 4–8. A sixth channel is then prepended (lines 148–150):

(5) Hbg(r, c) = 1 − maxi ∈ {1..5} Hi(r, c)

This is not a softmax normalisation — the six channels do not sum to 1, and each is regressed independently. The background channel acts as an explicit "nothing here" target, giving the network a supervised signal on empty regions instead of leaving them to be inferred from five near-zero channels. It also explains the model's output width: CPM(k=5) emits k + 1 = 6 channels (cpm_model_v2.py line 20).

2.5 The centre map

A seventh tensor is built at full resolution (lines 152–153) as a Gaussian at the canvas centre:

C(r, c) = exp( − [(c − 112)² + (r − 112)²] / 2·5² )

Its integral provides a useful sanity check on the implementation — for a continuous 2-D Gaussian, ∫∫ exp(−‖z‖²/2σ²) dz = 2πσ²:

2πσ² = 2π · 25 = 157.080   versus   measured sum = 157.080

The centre map tells the network which subject to attend to when several are present — the original CPM's mechanism for multi-person pose estimation. Here it is identical for every sample, since the crop always centres one specimen. It therefore carries no per-sample information and acts as a learned constant bias. This is why inference can build it once outside the image loop. It also means the crop step is not optional: the network has been told, by construction, that the subject is at the centre.

3. The architecture

Let I ∈ ℝ3×224×224 be the image and C ∈ ℝ1×224×224 the centre map. The model computes six heatmap predictions H(1)…H(6), each in ℝ6×28×28, and returns all of them (cpm_model_v2.py line 170).

3.1 Downsampling the centre map

C′ = AvgPool(C; k=9, s=8, p=1)

with output size given by the standard formula

⌊ (224 + 2·1 − 9) / 8 ⌋ + 1 = ⌊ 217/8 ⌋ + 1 = 27 + 1 = 28

matching the heatmap grid so it can be concatenated at every stage.

3.2 The shared trunk

_middle (lines 80–86) computes features reused by every refinement stage:

F = pool3( relu( conv3( pool2( relu( conv2( pool1( relu( conv1(I) ) ) ) ) ) ) ) )
    conv1: 3   -> 128,  9x9      pool: 3x3 stride 2
    conv2: 128 -> 128,  9x9      pool: 3x3 stride 2
    conv3: 128 -> 128,  9x9      pool: 3x3 stride 2
    F in R^(128 x 28 x 28)

Three stride-2 pools give total stride 2³ = 8, hence 224/8 = 28. The 9×9 kernels are unusually large by modern standards; Section 4 explains why that matters here.

3.3 Stage 1 — the initial estimate

_stage1 (lines 68–78) is a separate branch with its own copy of the trunk (conv1_stage1…conv3_stage1 are distinct parameters from conv*_stage2), followed by a predictor:

H(1) = g1(I)    where g1 ends 32 → 512 (9×9) → 512 (1×1) → 6 (1×1)

Note there is no activation on the final convolution, so H(1) is unbounded. Measured range of the trained stage-6 output on a real sample: [−0.027, 1.033] against a target range of [0, 1]. Values slightly outside [0,1] are expected, not a defect — the model is performing regression, not classification.

3.4 Stages 2–6 — the refinement recurrence

This is the heart of the architecture. Each subsequent stage is a function of the trunk features, the previous stage's output, and the centre map:

(6) H(t) = gt ( At(F) ⊕ H(t−1) ⊕ C′ ),    t = 2, …, 6

where ⊕ is channel concatenation and At is a 5×5 adapter reducing 128 channels to 32. The concatenated width is

32  +  (k+1)  +  1  =  32 + 6 + 1 = 39

which is exactly the input width declared at cpm_model_v2.py line 30, 32 + self.k + 2. Each gt is then three 11×11 convolutions followed by two 1×1 convolutions.

The essential point about (6) is that the previous prediction is an input, not just an output. Stage t can therefore condition landmark 4's position on where it currently believes landmarks 5–8 are. The network learns the joint spatial configuration of the landmark set — an implicit shape model — rather than five independent detectors.

4. Receptive fields: why six stages

This is the single most important quantitative argument in the architecture, and it is the reason the design looks so parameter-hungry. The receptive field of a stacked convolution obeys the recurrence

(7) Rℓ = Rℓ−1 + (kℓ − 1) · jℓ−1,     jℓ = jℓ−1 · sℓ

where R is the receptive field in input pixels and j the cumulative stride ("jump"). Applying (7) to this network:

Point in the networkReceptive fieldWhat it can see
Trunk output F71 pxa local patch — one leg joint, part of the body
Stage 1 output167 pxmost of the specimen, but not the whole canvas
Stage 2 output343 pxexceeds 224 — the entire image
Stage 3 output583 pxwhole image, with margin
Stage 4 output823 pxwhole image
Stage 5 output1063 pxwhole image
Stage 6 output1303 pxwhole image, ≈ 5.8× over
Measured by applying recurrence (7) to the actual kernel and stride sequence in cpm_model_v2.py.

Read the table as the design rationale. Stage 1 is a local detector: with a 167 px view it can find things that look like a landmark, but it cannot tell landmark 5 from landmark 7 if they are locally similar, because it cannot see the rest of the animal. From stage 2 onward every prediction is a function of the entire image, so the network can enforce global consistency — "this candidate cannot be landmark 8, because landmark 4 is over there."

Each 11×11 convolution contributes 10 pixels × jump 8 = 80 px of receptive field, and each stage stacks three of them, adding 240 px per stage. That is precisely why the kernels are large and why the parameter count is concentrated there: the stages buy context, and context is what disambiguates landmark identity.

Empirical confirmation Measured per-stage error on a trained sample (Section 5.3) drops sharply from stage 1 to stage 2 — raw MSE 0.0193 → 0.0111, a 43% reduction — exactly where the receptive field crosses the image boundary. It then flattens and is essentially converged by stage 4.

5. Training

Implemented in train_heatmap.py.

5.1 The loss and intermediate supervision

Lines 159–161 compute:

(8) 𝓛 = Σt=16 λ · MSE( H(t), Htarget ),     λ = 4704

The sum over all six stages — not just the final one — is intermediate supervision, and it is what makes a network this deep trainable. Without it, the gradient reaching stage 1 would have to traverse five refinement blocks; with it, every stage receives a direct gradient from the loss:

∂𝓛 / ∂θt = λ ∂MSE(H(t)) / ∂θt  +  Σt′>t λ ∂MSE(H(t′)) / ∂θt

The first term is a short path that cannot vanish regardless of depth. This is the same principle as auxiliary classifiers in GoogLeNet, and it predates residual connections as a solution to the same problem.

5.2 What heat_weight actually does

Line 140 sets heat_weight = 28 * 28 * 6 = 4704. This number is not arbitrary: it is exactly the number of elements per sample in the heatmap tensor. PyTorch's MSELoss defaults to reduction='mean', averaging over all N·C·H·W entries. Multiplying by C·H·W converts that into a sum over the heatmap and a mean over the batch:

λ · (1 / NCHW) Σn,c,h,w (·)²  =  (1 / N) Σn Σc,h,w (·)²

So the design intent is the classical CPM objective — total squared error over the heatmap, averaged over the batch. The practical effect is a ×4704 increase in gradient magnitude relative to a bare mean, which must be read together with the learning rate: the default --lr 1e-4 is small precisely because the loss is large.

5.5 Augmentation as a group action

Lines 126–132 apply two independent flips with probability ½ each. Because a coordinate is normalised to [0,1] over the whole canvas, the label transform is the corresponding reflection:

σx: (u, v) ↦ (1 − u, v)      σy: (u, v) ↦ (u, 1 − v)

This is geometrically correct despite the asymmetric bottom-right padding, because the flip is applied to the full canvas and the normalisation is canvas-relative, so both content and padding reflect together.

The two independent flips generate the Klein four-group V4 = {e, σx, σy, σxσy}, each element sampled with probability ¼. Note that σxσy = rotation by 180°, so the group contains two reflections (which reverse chirality) and one proper rotation (which does not). For specimens on a slide in arbitrary orientation this is a defensible choice; see Section 8.5 for the caveat about landmark identity.

6. Decoding: heatmaps → coordinates

Inference inverts Section 2. Implemented in infer_unlabeled.py, lines 53–60 and 219–221.

6.1 Soft-arg-max

The naive decoder is arg max, but it quantises to whole cells — 8 px in canvas space. Instead a weighted average is taken over the k strongest cells:

(11) wj = exp(sj) / Σm=1k exp(sm)
(12) x224 = 8 · Σj wj cj,      y224 = 8 · Σj wj rj

where sj are the top-k heatmap values and (cj, rj) their grid coordinates, recovered from the flat index nj by

cj = nj mod 28,     rj = ⌊ nj / 28 ⌋

since the flattening is row-major, n = r·28 + c.

The softmax in (11) is nearly uniform

This is a real weakness of the decoder as written. The sj are raw regression outputs in roughly [0, 1], so the largest achievable weight ratio is

exp(1) / exp(0) = e ≈ 2.718

Equation (12) is therefore much closer to an unweighted mean of the top-k cells than to a peak-weighted estimate. On well-behaved images this is harmless because the top cells are adjacent — measured difference between --topk 5 and --topk 1 on the test images was about 10 px. It fails when a channel is bimodal: the estimate lands between the two peaks, on neither. Introducing a temperature, wj ∝ exp(sj/T) with T ≪ 1, would sharpen it toward a true arg max.

6.2 Inverting the geometric transform

Composing the inverses of (3), (2) and (1) in reverse order gives a pure affine map:

(13) X = x224 / s + x1,      Y = y224 / s + y1

No padding term appears, which is a direct consequence of the encoder padding only the bottom and right. Had it padded symmetrically, (13) would need an extra offset of (224 − s·wcrop)/2.

One heatmap cell corresponds to 8/s original pixels, and s depends on the box. This makes the achievable precision image-dependent:

6.4 Dropping the background channel

Before decoding, inference discards channel 0 (final = final[:, 1:]). This is mandatory: channel 0 is the background map of equation (5), whose arg max is wherever landmarks are absent. Decoding it produces a spurious sixth "landmark", and — worse — shifts every subsequent index by one. This is the defect present in the older inference.py at line 195.

7. A complete worked example

Taking a real annotation and pushing it through encode → decode, with no network involved, isolates the precision cost of the representation itself.

Comparing step 7 against the original annotation (946.40, 872.41):

round-trip error = ( −1.5, −38.2 ) original pixels

The x error is small by luck; the y error is large because 0.2047 × 28 = 5.73 and the floor at step 5 discards 0.73 of a cell. With a crop this large, s = 0.153 means one cell spans 52.2 original pixels, so 0.73 cells is 38 px.

What this example establishes This is not model error — no network was run. It is the error floor imposed by the 28×28 grid, and it applies to the training targets as much as to predictions. The labels the model learns from are themselves quantised this coarsely. Two consequences follow. First, no amount of training can push accuracy below this floor with this stride. Second, the soft-arg-max of Section 6.1 partially recovers sub-cell precision at inference, which is exactly why it exists — but the encoder has no corresponding mechanism, so the targets stay quantised. Encoding the Gaussian at the unrounded position (dropping the floor at line 140–141) would cost nothing and remove this asymmetry.

8. Verified issues

Each item below was confirmed by executing the code, not by inspection alone.

8.1 train_heatmap.py depends on DDP to run at all

Lines 153–155 move images and targets to the GPU but pass centermaps straight from the loader, still on the CPU. Since forward concatenates it with GPU tensors (line 91), this should fail — and it does:

>>> m = CPM(5).cuda(); m(img_cuda, centermap_cpu)
RuntimeError: Expected all tensors to be on the same device, but found at least
two devices, cuda:0 and cpu! (when checking argument for argument tensors in
method wrapper_cat)

It works in practice only because line 44 wraps the model in DistributedDataParallel(..., device_ids=[args.gpu]), and single-device DDP scatters inputs onto the target device before calling forward. Verified:

>>> ddp = DistributedDataParallel(CPM(5).cuda(), device_ids=[0])
>>> ddp(img_cuda, centermap_cpu)[-1].device
device(type='cuda', index=0)      # DDP moved it silently

The practical consequence: you cannot debug this script single-GPU without DDP. Removing the wrapper — the natural first step when diagnosing a training problem — makes it crash with an error that points at the model rather than at the missing .cuda(). Adding centermaps.cuda(non_blocking=True) at lines 155 and 211 removes the hidden dependency at no cost.

8.2 lmk_mask is computed and discarded

Lines 121–124 build a per-landmark mask that zeroes landmarks 3 and 7 for profile views, but __getitem__ returns only image, heatmaps, centermap at line 160. The mask never reaches train_heatmap.py, whose loss at line 161 is unmasked. The older coordinate pipeline did use it (train.py line 155), so this appears to have been lost in the port.

The concrete effect runs through lines 93–95, which fill missing profile landmarks by duplication:

lmks[3-1] = lmks[2-1]      # kp3 := kp2 — later discarded by the channel selection, harmless
lmks[7-1] = lmks[5-1]      # kp7 := kp5 — RETAINED as channel 4, and trained on

328 of the 755 annotated images are profile views, so for 43% of the training set the model is taught that landmark 7 coincides with landmark 5. Predictions are consistent with this: on the inference test images kp5 and kp7 land about 9 px apart on one and share an identical y on another. Treat kp7 as unreliable and do not use the kp5–kp7 distance as a morphometric feature.

8.3 σ = 5 is very broad for a 28×28 map

As derived in Section 2.3, the support radius is 15.19 cells on a 28-cell map, and the target changes by only 2% for a one-cell displacement. The gradient signal for precise localisation is correspondingly weak. Reducing σ to 1–2 cells is the standard setting and would sharpen predictions, but requires retraining and may need a lower learning rate, since sparser targets increase gradient variance.

8.4 Argument order at the gaussian call sites

The function signature is gaussian(x, y, H, W) with H rows and W columns, and the body is self-consistent — verified by constructing a deliberately non-square map, where gaussian(x=5, y=20, H=40, W=20) correctly peaks at (row 20, col 5). The call sites, however, pass width into H and height into W: line 142 passes (w//stride, h//stride) and line 153 passes (w, h). This is harmless today only because the canvas is square, so both arguments are equal. It would silently transpose every target if target_size ever became non-square.

8.5 Flips do not relabel landmarks — verify this against your protocol

The flip augmentation of Section 5.5 transforms coordinates but leaves landmark identities untouched. In human pose and face alignment this is a known error: a horizontal mirror maps the left elbow onto the right elbow, so the label indices must be swapped as well, otherwise the network receives contradictory targets for the same visual pattern.

Whether this applies here depends on anatomy the repository does not record — the annotations store only integer IDs. There is circumstantial reason for concern: landmarks 3 and 7 are precisely the two absent from profile views (deducible from kp_6map8, whose image is {1,2,4,5,6,8}), which is what one expects of a bilaterally symmetric pair. If any of landmarks 4–8 form a left/right pair, the flip augmentation is injecting label noise. The check is quick: plot several annotated specimens with landmark IDs drawn, and see whether mirroring maps the set onto itself with identities preserved. If not, add the corresponding index permutation inside the flip branches.

8.6 The train/test split is deterministic by file order

Lines 50–63 sort images by class, then take the first 80% for training and the last 20% for testing, with no shuffling. Filenames are sequential (Entomobryomorpha_000048, …049, …060), which for a microscopy session usually means consecutive frames of the same or adjacent specimens. Near-duplicate frames straddling the 80% boundary would leak between the splits and make validation loss optimistic. Worth verifying before quoting any validation number; grouping the split by specimen rather than by index would settle it.

8.7 Refinement saturates before stage 6

From the measured table in Section 5.3, stage 4 achieves the lowest error and stages 5–6 are marginally worse. If this holds across the validation set, a 4-stage model would save roughly 9 M parameters and two-thirds of the refinement compute at no accuracy cost. Single-sample evidence — treat as a hypothesis to test, not a conclusion.
